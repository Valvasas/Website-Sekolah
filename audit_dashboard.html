5 Kelemahan Paling Krusial
BLOCKERsql.js bukan database yang tepat untuk production serverArsitektur

sql.js berjalan sepenuhnya di RAM (in-memory). Setiap server restart — crash, deploy ulang, mati listrik — semua data yang belum ter-flush ke file .bin hilang permanen. Window data loss bisa sampai 30 detik. Fatal untuk data ujian & nilai siswa.

✅ Fix: Migrasi ke better-sqlite3 — drop-in replacement, API hampir identik, langsung write ke disk, thread-safe. Estimasi 2–4 jam kerja.
💡 Kenapa krusial: Satu crash = data ujian CBT hilang, data PPDB hilang, nilai siswa hilang. Tidak ada recovery.
BLOCKERLMS.js & cbt.js 100% dummy data — tidak terhubung ke backendIntegrasi

Semua data di LMS (DATA_KELAS, DATA_TUGAS, DATA_NILAI, DATA_FORUM) adalah array JavaScript hardcoded. Backend sudah punya /api/siswa/nilai, /api/siswa/kehadiran, /api/siswa/jadwal tapi tidak dipakai. Semua siswa melihat nilai yang sama persis.

✅ Fix: Ganti semua DATA_* dengan fetch ke API pada initDashboard(). Backend sudah siap, tinggal koneksikan.
💡 Ini secara harfiah membuat LMS tidak berguna untuk operasi sekolah sungguhan.
BLOCKERTidak ada sistem upload file yang bekerja (tugas, foto profil, berkas PPDB)Fitur Hilang

Tiga titik upload: (1) lampiran tugas LMS, (2) foto profil user, (3) berkas PPDB (KK, akta, ijazah). Semua punya UI yang bagus tapi tidak ada handler backend. Multer sudah di-install tapi tidak ada route yang menggunakannya. File yang di-"upload" langsung dibuang.

✅ Fix: Buat route POST /api/upload dengan Multer, validasi tipe & ukuran, simpan ke backend/public/uploads/, return URL. Hubungkan ke frontend.
💡 PPDB tanpa upload berkas = pendaftaran tidak sah secara administratif.
HIGHTidak ada halaman/panel untuk guru input nilai & kehadiranFitur Hilang

Backend punya POST /api/siswa/nilai dan POST /api/siswa/kehadiran yang diproteksi untuk role guru/staff. Tapi tidak ada UI. Guru tidak bisa input nilai dari mana pun selain curl/Postman.

✅ Fix: Tambahkan tab "Input Nilai" dan "Input Kehadiran" di admin-panel/dashboard.html dengan tabel per-kelas.
💡 Ini adalah core function sebuah sistem informasi akademik. Tanpa ini, LMS hanya jadi website statis.
HIGHauth-guard.js tidak ada — halaman sensitif bisa diakses tanpa loginSecurity

README menyebut ada auth-guard.js tapi file ini tidak ada di codebase. LMS.html, cbt.html, DATA.html tidak punya proteksi redirect jika token tidak ada atau expired. User bisa langsung akses URL tanpa login.

✅ Fix: Buat frontend/auth-guard.js yang cek localStorage token + hit /api/auth/check, redirect ke login jika gagal. Embed di setiap halaman yang butuh auth.

User Flow Yang Tidak Bisa Diselesaikan
BLOCKERGuru tidak bisa melakukan tugas utamanya dari sistem iniUser Flow

Flow guru: Login → Lihat siswa per kelas → Input nilai → Input kehadiran → Upload materi → Buat soal CBT → Generate token ujian → Monitor live. Dari 7 langkah ini, hanya login dan monitor live (partial) yang bisa dilakukan. Sisa 5 langkah tidak ada UI-nya.

💡 Sistem ini tidak bisa menggantikan buku nilai & absensi manual. Guru masih butuh cara lain.
BLOCKERSiswa login ke LMS tapi semua data yang dilihat adalah palsuUser Flow

Siswa login → Melihat nilai 82 → Padahal itu DATA_NILAI hardcoded yang sama untuk semua user. Semua siswa melihat nilai, tugas, dan kelas yang identik. Forum post hilang saat refresh. Ini bukan hanya bug — ini menyesatkan user secara aktif.

✅ Priority fix: Connect LMS.js ke /api/siswa/nilai dan /api/siswa/dashboard minimal untuk data personal siswa.
HIGHMobile CBT tidak layak untuk ujian resmi di Android budgetResponsive

Di layar 360px (Android murah yang banyak dimiliki siswa SMK): nav grid soal terlalu kecil, teks soal overflow, timer box terpotong. Fullscreen API tidak support di banyak Android budget — siswa langsung gagal pre-check dan tidak bisa ujian sama sekali.

✅ Fix: Fullscreen API harus jadi opsional (warn, bukan block) di mobile. Nav grid pakai touch target min 44px.
HIGHTidak ada feedback loading state di form-form krusialMicro UX

Saat submit PPDB: tidak ada loading state. Saat login gagal LMS: tidak jelas apakah karena password salah atau server down. Admin panel: tidak ada indikator saat save data. User tidak tahu apakah aksinya berhasil atau tidak.

✅ Fix: Loading state (disabled button + spinner) untuk semua form submit. Error state yang deskriptif per field.
MEDIUMTidak ada onboarding untuk user baru (siswa, orang tua)UX

User baru tidak tahu: apa itu LMS, cara login CBT, cara cek status PPDB, atau URL mana yang harus dibuka. Tidak ada halaman "Panduan" atau tooltip. Satu-satunya hint adalah demo credentials di login page.

✅ Fix minimal: Tambahkan halaman /panduan.html dan link dari navbar utama. Atau tambahkan tooltip di form-form kritis.
BLOCKERsql.js harus diganti better-sqlite3 sebelum go-liveDatabase

Masalah sql.js: (1) In-memory — data loss saat crash. (2) Tidak thread-safe — concurrent request bisa corrupt data. (3) Lambat untuk read-heavy karena load seluruh DB ke RAM. (4) File .bin bisa ratusan MB untuk data sekolah besar.

✅ Migrasi: npm install better-sqlite3 → update config/database.js wrapper → semua query SQL tetap sama. Estimasi 2–4 jam kerja.
💡 Tanpa ini, semua data hilang saat server crash. Ini prerequisite untuk production, bukan nice-to-have.
HIGHTidak ada sistem logging yang proper (hanya console.error)Observability

Semua error hanya di-log via console.error(). Di production, log ini hilang saat server restart. Tidak ada log rotation, tidak ada error tracking, tidak ada cara debugging masalah production tanpa akses SSH real-time.

✅ Fix minimal: Install winston, log ke file /logs/app.log dengan rotation harian. Fix proper: Integrate Sentry untuk error tracking otomatis.
HIGHTidak ada PM2 config & health monitoring di productionDevOps

README menyebut PM2 tapi tidak ada ecosystem.config.js. Tidak ada health check yang monitor memori/CPU. Tidak ada alerting jika server down. Jika server crash tengah malam pas ujian besok pagi, tidak ada yang tahu.

✅ Fix: Buat ecosystem.config.js untuk PM2 dengan restart policy, memory limit, dan log file. Update /api/health endpoint agar return status DB + uptime + memory usage.
MEDIUMStatic files tidak di-cache — lambat di koneksi WiFi sekolah ramaiPerformance

Server Express serve semua static files tanpa cache headers. Setiap request ke cbt.css, cbt.js, lms.css, lms.js akan download ulang. Di WiFi sekolah dengan 100 siswa ujian serentak, ini berarti bandwidth tinggi dan load time lambat.

✅ Fix: Tambahkan express.static(path, { maxAge: '1d' }) untuk asset files. Atau pasang Nginx di depan Express sebagai reverse proxy + static file server.
MEDIUMTidak ada config validation terpusat saat startupConfig

Nilai env seperti LOGIN_MAX_ATTEMPTS, EMAIL_HOST dibaca dengan process.env.X || defaultValue di berbagai file. Tidak ada validasi terpusat. Jika .env salah isi, sistem jalan tapi dengan behavior tidak terduga — bukan crash dengan pesan jelas.

✅ Fix: Buat backend/config/env.js yang validasi semua env vars saat startup dan throw error deskriptif jika ada yang salah atau tidak sesuai format.
